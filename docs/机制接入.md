# M01–M05 机制接入（0.2.0-rc.2）

本节 API 来自不可变标签 `0.2.0-rc.2`。core 和可选 dingtalk 模块使用同一版本；JitPack 13 个模块已公开，独立远程消费结果记录于 VALIDATION.md。

## Android 日志和异常

组件持有一个 `DiagnosticStore`，日志只经过一个 `DiagnosticWriter`。宿主保留时间/线程/level/tag 格式与 Debug Logcat，将已经脱敏的文本提交队列：

```kotlin
val store = androidDiagnosticStore(context)
val writer = DiagnosticWriter(store) // 默认最多排队 1024 条；满时拒绝提交，调用方处理失败。
writer.append(hostFormattedLine)
writer.flush() // 默认 5 秒；超时、中断、之前的落盘失败向调用方报告。
val recorder = AndroidCrashRecorder(
    store,
    flush = writer::flush,
    onUncaughtException = { thread, error -> hostLogCrash(thread, error) },
)
// 停止生产日志与采集后依次 recorder.close(); writer.close(); store.close()。
```

handler 安装互斥，重复创建被拒绝，不叠加链；保留原 handler。异常原文使用 `boundedThrowableReport` 保持 512 KiB UTF-8、UTC 时间、cause/suppressed 和去环，关闭后不能通过旧 handler 重启采集。落盘、宿主回调、flush 失败均继续原 handler。崩溃现场仅持久化，调度与通知时机仍由宿主下一次启动决定。`DiagnosticWriter.close()` 不关闭共享 store，落盘失败会使 flush 报错；后续真实写入恢复成功后才清除错误，兼容宿主原有恢复语义。

## 旧目录恢复与只读导出

仅为已知旧目录注入迁移规则，不扫描父目录，不创建第二个批次所有者：

```kotlin
val store = DiagnosticStore(
    componentPrivateDirectory,
    legacySources = listOf(
        LegacyDiagnosticSource(oldPendingDirectory, listOf("app_", "crash_", "anr_"), frozen = true),
        LegacyDiagnosticSource(oldLogDirectory, listOf("app_")),
        LegacyDiagnosticSource(oldCrashDirectory, listOf("crash_")),
    ),
)
val batch = store.prepareBatch()
// 原有 openFile/read/close 协议不变。取消、失败、部分成功时不调用 acknowledgeBatch。
// 只有整批完成后：store.acknowledgeBatch(batch)
```

旧冻结目录优先。合法旧 `batch-id` 继续使用；不存在时生成一个持久 ID。旧冻结批次超过当前容量时失败保留，不能拆成两个成功批次。迁移先按快照长度流式复制进 staging，然后原子公开到现有 pending；失败不删除源。restart 复用同一个批次。最终 ack 逐字节比较旧原件，仅删除仍与冻结副本相同的原件；修改后的旧原件和之后的新组件日志保留。迁移规则必须在旧数据排空前持续配置；不要让旧 owner 再写这些目录。

`currentFiles()` 不冻结、不切卷。`DiagnosticSnapshotFile(path,name,size)` 区分 active/frozen 同名文件。`openSnapshot` 只读快照长度；`readTail` 使用 Android/JVM seek 或 Native POSIX seek，`dropPartialFirstLine=true` 可去掉截断的首行。`DiagnosticFiles` 提供显式私有文件列表、`snapshot(path)`、尾读、流式比较和 SHA-256 指纹；指纹兼容历史通知去重，删除仍逐字节核验。

### 原子只读 reader 快照（rc.12）

以下 `openCurrentSnapshot`、`DiagnosticReadSnapshot` 和已打开快照导出 overload 从 `0.2.0-rc.12` 起提供，
不在 `0.2.0-rc.11` 中；正式接入前核对同版 Release 与远程消费门禁。

活动 store 的完整导出使用 `openCurrentSnapshot()`：组件在同一实例锁内枚举并打开全部 reader，随后立即解锁。
后续 append/rotate、prepareBatch 移动文件以及成功上传后的 ack 删除路径，都不会让导出重新读取同名新文件。
快照只包含捕获的文件和长度，后来的追加、新报告留给下次导出；不冻结、确认或删除批次。
ZIP 压缩、文本写入和宿主 metadata 计算不持有 store 锁，因此慢导出不阻塞新崩溃报告落盘。
Android `AnrReportStore.openCurrentSnapshot()` 在其自身监视器内同样打开全部报告，避免保留窗口淘汰导致路径失效。
不同 store 的快照分别捕获，不承诺跨 store 同一时刻的全局事务。

```kotlin
// 需要包含此前排队日志时先 writer.flush()；flush 本身不能保护随后路径枚举与打开的间隙。
// common/iOS：原始描述不 copy，名称映射只影响文本标题。
store.openCurrentSnapshot().use { snapshot ->
    DiagnosticFiles.exportTextSnapshot(snapshot, privateDestination, hostHeader) { file ->
        hostFileName(file.name)
    }
}
// Android/JVM：另开一次快照，不能重复消费同一个 reader。
store.openCurrentSnapshot().use { logs ->
    anrStore.openCurrentSnapshot().use { anrs ->
        val files = (logs.files + anrs.files).distinctBy { it.path }
        exportDiagnosticZip(zipPath, listOf(logs, anrs), files.mapIndexed { index, file ->
            DiagnosticZipFile("files/$index/${file.name}", file)
        }, mapOf("metadata.json" to hostMetadataJson))
    }
}
```

`files` 是用于分类和映射归档名的原始描述；`snapshot.reader(file)` 返回已经打开的同一 reader，
不接受改过 name/size/path 的副本。文本 overload 可通过 `files = snapshot.files.filter { ... }` 选择授权子集，
省略时导出全部文件；未选择项仍由 snapshot 统一关闭，最终输出及其 `.tmp` 路径不得与任何输入快照源重合，
包括未选择项、owner 已删除的原路径及父目录符号链接别名。ZIP overload 借用 `snapshots` 中的 reader，不重新打开路径；
每个文件只消费一次，不得将同一描述重复放入多个 ZIP entry。旧路径 overload 继续兼容现有调用，
但 `currentFiles → openSnapshot/路径导出` 无法提供活动 store 的轮转安全；仅供已稳定且不会被其他 owner 移动/删除的文件。

调用方始终用 `use/finally` 关闭 snapshot，包括导出参数校验、metadata、读取和写入失败。
导出不关闭借用 reader；snapshot 的 close 幂等，关闭一项失败仍继续释放其余项，并保留主异常与 suppressed 错误。
Swift 直接持有快照时使用 `try snapshot.closeWithError()`，让文件关闭异常通过 NSError 返回；
Kotlin 继续使用 `use`。该 Swift 入口为当前 main 合并补丁，尚未包含在已发布的 rc.16 中，不能用旧坐标调用。
已经打开的句柄在 store.close 后仍由 snapshot 持有，须尽快关闭，不能依赖路径删除回收仍打开文件的空间。
旧目录必须停止原 owner 写入；实例锁不提供跨进程、跨实例或外部目录锁。

同版新增 `boundedNativeThrowableReport(error, maxBytes = 512 * 1024)`，供 iOS/OHOS 已捕获异常日志复用。
输出按 UTF-8 总字节数限长，cause/suppressed 共用 16 节点与深度预算，每个异常最多 100 帧，循环与超额有截断标记。
它仅格式化调用方提供的 Throwable，不安装新的未捕获异常、signal 或 OOM 采集器。

源文件不足快照长度时导出失败。导出不 ack，不删除源；本次创建的半成品 `.tmp` 失败后删除；
已有同名临时文件会拒绝导出，保留原证据。输出必须是新私有文件，不能覆盖任何源。
分享权限、缓存清理和用户确认继续由宿主负责。

## iOS JSON 解析

```kotlin
val parsed = IosSystemReportParser.parse(
    rawText = boundedFileText,
    source = SystemReportSource.METRICKIT, // 或 NS_EXCEPTION
    fallbackTimestampMillis = hostFileTimestamp,
    includeDetails = needsDetail,
)
// 宿主使用 fileName#section#index 维持旧展示 ID，按 kind 补充中文说明和建议。
```

输出是 `NeutralSystemReport`，保留时间、进程、时长、描述和有界调用树。支持五种稳定 MetricKit 数组、watchdog 细分、NSException。未知字段忽略，错误类型可选读取；畸形与超大输入返回 `INVALID_JSON`/`INPUT_TOO_LARGE`。输入默认最多 2 Mi 字符、详情 256 Ki 字符、数组总记录 100、字段查找深度 8/节点预算 10000；解析器前还限制结构嵌套为 64。原始系统文件通过导出机制保留，不扩大 MetricKit/NSException 采集。

## Ktor 日志块

```kotlin
val network = NetworkLogStore<HostEnvironment>()
if (hostDebugToolsEnabled) network.record(ktorBlock, hostEnvironment)
val records = network.records // StateFlow；宿主转换自己的 UI 模型。
```

组件不包含业务环境类型、门禁、Token 白名单、HttpClient 或页面文案。记录最多 100 条、每条副本最多 32 Ki 字符，原文的 `truncated` 状态供宿主展示。URL 保持原 Ktor REQUEST/FROM 格式（包括已有 query），组件不替宿主做脱敏。所有同步 record/clear 在同一锁内排序，ID 与列表顺序一致；Release 是否进入记录仍由宿主控制。

## 可选钉钉传输

Android/iOS/JVM/OHOS 需要时安装同标签的 `diagnostics-dingtalk`；core 不依赖该模块，OHOS 使用 Curl engine。模块使用独立 Ktor pipeline，5000ms timeout、禁止重定向、无 Logger；注入 client 时只借用其 engine，不继承宿主日志/业务插件，close 不关闭借用的 engine。默认 engine 由模块拥有并关闭。

```kotlin
val sender = DingTalkWebhookClient(webhook = hostWebhook, secret = hostSecret)
try {
    val result = sender.send(hostTitle, hostMarkdown)
    // result.status/httpStatus/errorCode；宿主决定提示、重试、去重和成功状态。
} finally { sender.close() }
```

凭据仅注入；`signedDingTalkWebhook` 限定官方 `https://oapi.dingtalk.com/robot/send`、443、无 userinfo/fragment/旧签名且含 access_token。HMAC-SHA256 使用 `timestamp + "\n" + secret`，Base64 后 URL 编码。HTTP/协议/传输失败明确区分；响应最多读取 16 KiB。原异常和服务端正文可能回显 URL/诊断文本，因此不放进结果日志；取消继续抛出，不转换成成功，关闭后拒绝发送。官方协议参考[自定义机器人接入](https://open.dingtalk.com/document/orgapp/custom-robot-access)。

Webhook、Secret、隐私/Session 准入、Markdown、提醒时机、通知状态、去重和重试全由宿主持有。契约测试只使用 MockEngine 和固定非真实测试签名，不发送真实消息。

## 可删除的宿主主体

完成候选版本的远程消费与薄接线后，可以删除 Android handler 链、Crash Throwable 遍历、executor/flush barrier、文件尾读/比较/指纹/ZIP 执行体、旧目录冻结与批次恢复执行体、iOS JSON 遍历/时间/数组解析、网络记录原子 owner、双平台钉钉 endpoint/HMAC/HTTP 执行体。保留 Logger 接口/Logcat/格式、旧目录前缀配置、文件分类与 metadata、DebugDiagnostic/UI 映射、业务环境门禁、隐私/Session、通知协调器和展示文案。不能把本地 staging 通过等同于这些宿主主体已经删除或远程发布已完成。
