```bash

bash gradlew :diagnostics-core:testDebugUnitTest --tests io.github.gycrosskit.diagnostics.AnrReportStoreTest --offline --max-workers=1
bash gradlew :diagnostics-core:jvmTest :diagnostics-core:testDebugUnitTest :diagnostics-core:compileDebugKotlinAndroid --offline --max-workers=1

xcrun --sdk iphonesimulator swiftc -typecheck ios-support/*.swift -target arm64-apple-ios14.0-simulator
bash gradlew :diagnostics-core:publishAllPublicationsToStagingRepository --offline --max-workers=1
bash gradlew -p verification-consumer -PdiagnosticsMavenRepo="$PWD/build/maven" jvmTest compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinOhosArm64 linkDebugFrameworkIosSimulatorArm64 linkDebugSharedOhosArm64 --offline --max-workers=1
# Maven 消费者 Framework 构建后，可联合验证 Swift 错误处理接线：
```

独立 `verification-consumer` 通过 exclusive Maven 仓库解析正式发布物，不使用 project dependency、includeBuild 或 mavenLocal。行为测试覆盖滚动容量、UTF-8、并发写入、重启批次复用、报告/批次容量、TAR 工具逐字节解包、归档损坏与写入中途失败保留源文件、确认只删原批次。

准确已执行结果记录在 [VALIDATION.md](../VALIDATION.md)。远程 Maven 消费结果见该记录；Android/iOS/OHOS 真机采集、系统真实 crash/hang 投递、后台退出与分享权限、真实业务宿主的 Swift/KMP 整合仍需设备验收。本库没有 OHPM 产物。

## 原生采集预发布

以下原生采集命令保留 `0.2.0-rc.1` 历史验收配置；当前 Core Maven 版本为 `0.2.0-rc.10`，包含本轮修复。最新源码验证范围见[功能与平台差异](功能与平台差异.md)。提供 `ANDROID_HOME` 或 Worktree 自己的 local.properties。

```bash
ANDROID_HOME=/path/to/android/sdk bash gradlew :diagnostics-core:testDebugUnitTest :diagnostics-core:jvmTest :diagnostics-core:publishAllPublicationsToStagingRepository --offline --max-workers=1
python3 jitpack-metadata.py build/maven
# 使用 organization-profile/templates/check-maven.py 检查所有实际产物、hash 和平台变体。
ANDROID_HOME=/path/to/android/sdk bash gradlew -p verification-consumer -PdiagnosticsMavenRepo="$PWD/build/maven" -PdiagnosticsVersion=0.2.0-rc.1 jvmTest testDebugUnitTest compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinOhosArm64 linkDebugFrameworkIosSimulatorArm64 linkDebugSharedOhosArm64 --offline --max-workers=1
swift build --package-path verification-consumer/ios-native --sdk "$(xcrun --sdk iphonesimulator --show-sdk-path)" --triple arm64-apple-ios14.0-simulator
swift build --package-path verification-consumer/ios-native --scratch-path build/swift-consumer-device --sdk "$(xcrun --sdk iphoneos --show-sdk-path)" --triple arm64-apple-ios14.0
pod lib lint GYDiagnosticsNative.podspec --allow-warnings --use-libraries
```

SwiftPM 消费者依赖本地 Package product，Pod lint 实际生成 Pod 消费工程并编译/import；这是本地验证入口。正式 Git 标签的远程 SwiftPM 与 Pod spec lint、正式 JitPack 多平台消费均已另行通过，结果见 VALIDATION。NSException/MetricKit/ANR 真机递送及宿主 Debug/QA 准入仍需设备验收。

## 正式远程消费

Maven consumer 不传本地仓库参数时仅从 JitPack 解析 diagnostics；指定已发布版本即可：

```bash
ANDROID_HOME=/path/to/android/sdk bash gradlew -p verification-consumer -PdiagnosticsVersion=0.2.0-rc.1 jvmTest testDebugUnitTest compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinIosX64 compileKotlinOhosArm64 linkDebugFrameworkIosSimulatorArm64 linkDebugSharedOhosArm64 --max-workers=1
# spec lint 按 podspec 中的 Git URL/tag 实际下载，与本地 lib lint 区分。
pod spec lint GYDiagnosticsNative.podspec --allow-warnings --use-libraries
```

SwiftPM 消费工程依赖 `.package(url: "https://github.com/gycrosskit/diagnostics.git", exact: "0.2.0-rc.1")` 的 `GYDiagnosticsNative` product，使用上文 SDK/triple 命令编译；本轮 Package.resolved 指向发布提交 `88091275f5bf8190a9510d12873a4e30181ba484`。

组织 Maven checker 用于原始 staging/Release 归档。JitPack 会把响应 metadata 的根 component identity 改为 `com.github.gycrosskit:diagnostics`，因此同一严格组名断言不能直接作为 JitPack 下载树的完整消费验收。本轮另校验实际二进制字节、variant 文件 size/hash/四种 Native target，并完成真实 Gradle 远程编译与链接；不改写远程 metadata。

## M01–M05 候选完整验证

`diagnostics-dingtalk` 现包含 Android/iOS/JVM/OHOS，不能只构建 core 或沿用旧7模块归档。根 staging 发布默认包含两个模块。归档安装脚本按整树解包，无模块白名单；新标签的 checksum 必须来自包含14个 publication 的新归档。

```bash
ANDROID_HOME=/path/to/android/sdk bash gradlew :diagnostics-core:jvmTest :diagnostics-core:testDebugUnitTest :diagnostics-dingtalk:jvmTest :diagnostics-dingtalk:testDebugUnitTest :diagnostics-core:iosSimulatorArm64Test :diagnostics-dingtalk:iosSimulatorArm64Test publishAllPublicationsToStagingRepository --offline --max-workers=1
python3 jitpack-metadata.py build/maven
python3 verification/check-maven.py build/maven com.github.gycrosskit.diagnostics 0.2.0-rc.5 diagnostics-core,diagnostics-dingtalk ios_arm64,ios_x64,ios_simulator_arm64,ohos_arm64
ANDROID_HOME=/path/to/android/sdk bash gradlew -p verification-consumer -PdiagnosticsMavenRepo="$PWD/build/maven" -PdiagnosticsClosure=true jvmTest testDebugUnitTest compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinOhosArm64 --offline --max-workers=1
# 正式发布后不传 staging 参数，固定真实新版本从 JitPack 独立消费；不要在发布前宣称远程已通过。
```

`diagnosticsClosure=true` 单独启用候选API/可选模块 consumer 源集；不加该参数仍可验证旧公开 core 版本。OHOS 同时消费 core 与通知模块；Curl 用于真实 HTTP transport，HMAC 复用 core 已有 SHA-256，最低 API 12 不依赖较新 Native Crypto API。iOS/JVM/Android 继续使用各平台现有 HTTP engine 与加密实现。
