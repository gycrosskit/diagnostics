# Diagnostics 开发与验证

## 日常构建入口

日常编译由项目维护命令，CI 只调用 `bash scripts/build.sh compile --platform android|ios|harmony`，不串联 MR、测试或独立消费者。Harmony compile 复用 `build/ohos-sdk-compile` 和 Hvigor 原生增量输出；已有 `build/ohos-sdk` 候选归档保持不变，独立 package 仍拒绝覆盖。平台参数每次选择一个；这里只编译生产模块，iOS/ArkTS 原生消费与设备验收分别记录。

iOS compile 先编译本库 Kotlin 生产目标，再用本库 Pod/SPM 生产 target 编译 Swift/ObjC；只执行 `xcodebuild build`，不运行测试或远程消费者。Native、SDK Core、Bugly、Umeng 分别编译，供应商适配器不放在同一目标里混装。

Maven 打包沿用项目脚本，通过 `VERSION=<不可变版本> bash scripts/build.sh package --platform maven` 调用，不上传、不创建 Tag；HAR 渠道通过 `package --platform harmony` 编译生产模块。发布任务复用既有 publisher、版本保护与 journal，未做消费时明确记录未消费，不把打包成功视为宿主验收。下文测试及消费命令按需要单独执行，不进入日常构建。

Diagnostics HAR 按生产依赖顺序执行 `--module core`、`--module bugly`、`--module umeng`；core 的本轮 HAR override 仍由受信发布入口核对并恢复。


当前版本及发布边界统一见 [README](../README.md)。

当前 SwiftPM fixture 与 Gradle consumer 默认值随统一候选同步；正式消费者仍由 `verify-tagged-ios-sdk.rb` 在隔离目录固定精确待验收 tag。

2026-10-25 起源码验证入口使用[统一远程验证（Jenkins）](https://github.com/gycrosskit/.github/blob/main/docs/统一远程验证.md)，GitHub Actions workflow 与专用 runner 脚本退出使用。以下带日期的旧 CI 记录仅说明当时结果；当前验证以实际源码 SHA 和 Jenkins 回执为准。

**最终核对入口（2026-10-08）**：[测试源码、执行平台、前轮复用与本轮重跑](功能与平台差异.md#验证结果与测试入口)。下列构建/发布命令与已有版本记录保留原范围，不能套用为本轮新执行结果。

从仓库根目录执行下列命令。staging 验证只证明本地发布物，公开 JitPack 的安装结果另见验证记录。

## OHOS Kuikly 桥轻量回归

`python3 verification/test_ohos_diagnostics_bridge.py` 使用已缓存的 Kotlin/JVM 工具编译真实 `OhosDiagnosticSdkBridge`，以 Renderer/Module 替身验证早期配置、64 份日志额度、页面重接、取消、销毁、同步回执及 callback 注册后 native 同步异常的清理。未加 `--resolve-dependencies` 时不下载依赖；不执行 Gradle 或 Native SDK 构建。异常回归在旧实现失败，修复后通过；替身中的注册顺序按固定 Kuikly `2.29.1` 核对，不证明真实 OHOS Renderer、HAR 链接或设备销毁行为。

## 本地验证

```bash
# ANR保留窗口专项：实际生产store+临时文件，非系统ANR触发。
bash gradlew :diagnostics-core:testDebugUnitTest --tests io.github.gycrosskit.diagnostics.AnrReportStoreTest --offline --max-workers=1
bash gradlew :diagnostics-core:jvmTest :diagnostics-core:testDebugUnitTest :diagnostics-core:compileDebugKotlinAndroid --offline --max-workers=1
bash gradlew :diagnostics-core:compileKotlinIosArm64 :diagnostics-core:compileKotlinIosSimulatorArm64 :diagnostics-core:compileKotlinOhosArm64 --offline --max-workers=1
bash gradlew :diagnostics-core:iosSimulatorArm64Test --offline --max-workers=1
xcrun --sdk iphonesimulator swiftc -typecheck ios-support/*.swift -target arm64-apple-ios14.0-simulator
bash gradlew :diagnostics-core:publishAllPublicationsToStagingRepository --offline --max-workers=1
bash gradlew -p verification-consumer -PdiagnosticsMavenRepo="$PWD/build/maven" jvmTest compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinOhosArm64 linkDebugFrameworkIosSimulatorArm64 linkDebugSharedOhosArm64 --offline --max-workers=1
# Maven 消费者 Framework 构建后，可联合验证 Swift 错误处理接线：
xcrun --sdk iphonesimulator swiftc -typecheck ios-support/*.swift verification-consumer/SwiftConsumer.swift -F verification-consumer/build/bin/iosSimulatorArm64/debugFramework -target arm64-apple-ios14.0-simulator
```

独立 `verification-consumer` 通过 exclusive Maven 仓库解析正式发布物，不使用 project dependency、includeBuild 或 mavenLocal。行为测试覆盖滚动容量、UTF-8、并发写入、重启批次复用、报告/批次容量、TAR 工具逐字节解包、归档损坏与写入中途失败保留源文件、确认只删原批次。

准确已执行结果记录在 [VALIDATION.md](../VALIDATION.md)。远程 Maven 消费结果见该记录；Android/iOS/OHOS 真机采集、系统真实 crash/hang 投递、后台退出与分享权限、真实业务宿主的 Swift/KMP 整合仍需设备验收。可选原生诊断适配分别提供 OHPM Core / Bugly / Umeng HAR，须独立验收。

## 源码 CI 编译缓存

以下为历史 Actions 缓存配置，仅用于原 tag/旧运行核对；当前源码 verify 的缓存与执行参数以[统一远程验证（Jenkins）](https://github.com/gycrosskit/.github/blob/main/docs/统一远程验证.md)及固定版本 recipe 为准。

源码 `android/native` jobs 使用固定 SHA 的 `gradle/actions/setup-gradle` 复用 Gradle User Home，并通过现有 init script 启用编译缓存。PR 只读缓存，完整源码 dispatch 与 main 可写入当前 ref 的缓存；源码修改仍由 Gradle 输入指纹决定是否重编译。仅工具链预热不恢复或保存此 Gradle 缓存，避免先占用同 SHA 的不可变 key 而阻止后续源码结果写入。

`AbstractTestTask` 禁用缓存及 up-to-date 跳过，行为测试每次实际执行；原编译目标、Simulator/Swift 检查、链接、超时与门禁保持不变。发布 jobs 不启用本策略，保留原精确版本及依赖刷新验证。冷暖耗时必须绑定同一 SHA 与完整源码运行，不能把缓存预热或普通 main push 的轻量检查算作源码通过。

依赖缓存沿用调用方提供的 `GRADLE_USER_HOME`、`KONAN_DATA_DIR`、`CP_CACHE_DIR`、`GRADLE_RO_DEP_CACHE`，编译与打包使用同一组目录。项目入口不清理这些缓存，也不强制刷新依赖；Maven、Google 与插件仓库镜像由本项目 `settings.gradle.kts` 和已有 `scripts/ci-repositories.gradle`（如存在）维护。CI 仅统一 GitHub 出站代理。

本轮 Gradle Wrapper 仍为 `8.11.1`，显式使用已登记 Aliyun Gradle 分发镜像并固定官方 SHA-256，直接复用受管同版本缓存；不升级 Gradle、AGP 或厂商 SDK，不复制个人缓存。

项目打包入口保留 `settings.gradle.kts` 声明的 Aliyun Maven 镜像；`ci-repositories.gradle` 仅限制 Eazytec 的定制 Kotlin 解析范围，不再删除项目镜像。
