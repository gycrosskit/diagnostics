# 原生采集接入

本指南保留原生包 `0.2.0-rc.1` 的历史发布与验收记录；当前 Core Maven 发布候选为 `0.2.0-rc.11`，包含既有 native历史收集/OHOS分类修复和新增 Ktor 文件桥接，见[功能与平台差异](功能与平台差异.md)。原生包 `0.2.0-rc.1`：正式 JitPack、Swift Package Git tag 与 Pod Git tag 消费均已通过，实际范围见 VALIDATION。Android ANR 在 `diagnostics-core` Android 变体内；Swift 原生采集是独立的 `GYDiagnosticsNative` Package/Pod。KMP 的报告 store 默认 5 份/512 KiB，不替代下列历史 ANR 与 iOS 分类存储。

## Android ANR

```kotlin
import io.github.gycrosskit.diagnostics.AndroidAnrMonitor
import io.github.gycrosskit.diagnostics.AnrLogLevel
import io.github.gycrosskit.diagnostics.AnrReportStore

// Debug/QA、隐私准入与应用单例的安装位置由宿主决定。
val reports = AnrReportStore(applicationContext)
val monitor = AndroidAnrMonitor(applicationContext, reports) { level, tag, message ->
    when (level) {
        AnrLogLevel.INFO -> hostLogger.i(tag, message)
        AnrLogLevel.WARNING -> hostLogger.w(tag, message)
    }
}
monitor.start()
// 后台读取列表/详情和打包：
val summaries = reports.summaries()
val detail = summaries.firstOrNull()?.let { reports.report(it.id) }
val files = reports.pendingReportFiles()
// 宿主串行启停；撤回 Activity 监听、终止工作线程并等待已开始的采集完成。
// close 同步 drain；系统 trace 的 I/O 没有期限，不能在 UI 主线程等待。
monitor.close()
```

- `AnrReportStore(Context)` 保持 `noBackupFilesDir/anrs`，也提供 `AnrReportStore(File)` 注入专属目录。同一目录由一个实例管理，不提供跨进程锁。
- 保持 `anr_system_<timestamp>_<pid>.txt` / `anr_watchdog_<timestamp>_<pid>.txt`、`formatVersion=1`、所有头字段和三段线程文本。系统历史按稳定文件名去重，已被留存策略淘汰的历史条目可再次导入。
- 最多保留 10 份，单份最多 256 KiB；流式 UTF-8 写入预留截断标记，临时文件原子 rename 后才可见。概览只读取头；详情最多读取 256 Ki 字符；非法路径/临时文件拒绝读取。
- API 30+ 导入最多 16 条系统退出记录，系统 trace 最多 192 Ki 字符。主线程看门狗阈值 5 秒，同一次卡顿只采样一次，恢复后继续。主线程最多 100 帧/48 Ki 字符，其他线程最多 30 个、各 80 帧/8 Ki 字符，总转储最多 128 Ki 字符，枚举最多 64 个线程。
- `AnrReport`、`AnrReportSource`、`AnrReportSummary`、`StoredAnrReport`、`analyzeAnr` 与 `extractMainThreadTrace` 可供宿主直接 import。宿主原 `AnrMonitor` 接口若必须保留，只包装 `start()` 委托，不复制采集代码。
- Android `BoundedReportWriter(Writer, maxBytes, truncationMarker)` 同时供 ANR 和宿主 Crash 文本格式使用；UTF-8 字节预算已为 marker 预留空间，保留代理对边界。宿主提供 Crash marker 和自己的预算，不需要复制 writer；追加完后只调用一次 `finish()`，组件不关闭宿主 Writer。
- 看门狗是卡顿现场，不能当作系统最终 ANR 事实。OOM 等采集失败只回调固定短消息，避免错误处理再次序列化巨大异常栈。日志回调须快速返回；`close()` 同步等待线程退出，系统 trace 的 I/O 没有期限，必须由宿主在后台执行，不应与回调形成相互等待。

## Android native crash 历史（0.2.0-rc.9）

与 JVM CrashRecorder / ANR monitor 分开显式启用：`AndroidNativeCrashCollector(context, store).start()`。API30+ 导入 native 退出元数据，API31+ 仅保存系统仍保留的有界 tombstone protobuf Base64，未解析、无 signal handler、无自动上传；不覆盖 API24–29。共享 Store 配一个 collector，先 close collector 再 close store。collector.close 不等待系统 trace；这与上述 ANR monitor 的同步 close 不同。去重、noBackup 建议及两次原子写入可重复边界见[功能与平台差异](功能与平台差异.md)。

## iOS Swift Package / Pod

Swift Package 使用 `https://github.com/gycrosskit/diagnostics.git` 的不可变 tag `0.2.0-rc.1`；根清单提供 `GYDiagnosticsNative` product，最低 iOS 14。宿主选择一个原生包入口，不再把相同 Swift 文件直接复制进 target。

```ruby
# 无 CocoaPods Specs 坐标；直接使用同一不可变 Git 标签。
pod 'GYDiagnosticsNative', :git => 'https://github.com/gycrosskit/diagnostics.git', :tag => '0.2.0-rc.1'
```

```swift
import Foundation
import GYDiagnosticsNative

let library = FileManager.default.urls(for: .libraryDirectory, in: .userDomainMask)[0]
let collector = GYDiagnosticCollector(
    directory: library.appendingPathComponent("SkillCureDiagnostics", isDirectory: true)
)
// 应用持有一个实例，在主线程调用，启用条件由宿主决定。
collector.start()
// 撤回 Subscriber 和自己安装的 NSException handler，并等待已接受的队列写入。
collector.stop()
```

原宿主 `DiagnosticCollector.shared` 可只持有上述实例并转发 `start()`。目录注入保持既有 `Library/SkillCureDiagnostics`，宿主已有文件读取、摘要、分享/上传不用改变。

- `MXMetricPayload` 写为 `metrickit_metric_<timestamp>_<UUID>.json`；`MXDiagnosticPayload` 写为 `metrickit_diagnostic_<timestamp>_<UUID>.json`；未捕获 `NSException` 保持 timestamp/name/reason/callStackSymbols JSON 写为 `crash_<timestamp>_<UUID>.json`。
- 三类分别保留最新 10 份，原子写入。MetricKit 在串行后台队列写入；NSException 在异常线程同步保存，避免进程退出前队列未执行。文件锁避免异常写入和 MetricKit 裁剪互相竞争。
- 兼容 `GYMetricKitRecorder(record:)` 与 `record:onReportStored:`，它继续把 diagnostic JSON 交给 KMP store；与新 Collector 共用单一进程所有者，重复启动另一 API 会明确拒绝，先停止现有实例才能切换。进程所有权门会强持有当前实例，释放宿主引用不等于停止，必须显式调用 `stop()`。
- 采集器不安装 signal handler，不保证 Swift fatalError、Native signal、OOM 或硬杀时即时保存。MetricKit 是系统延迟投递，编译或模拟回调不能证明真机最终递送。
- NSException 保存后转交安装前的 handler；stop 仅在当前仍是自己安装的 handler 时恢复旧 handler。与第三方 crash SDK 的 handler 链仍由宿主按安装顺序管理。

## 验证范围

`verification-consumer/ios-native` 是独立的 Package 消费工程，实际依赖 product 并编译薄宿主，Maven 消费工程实际编译 Android ANR public API。命令及本轮结果见[开发与验证](开发与验证.md)与 [VALIDATION](../VALIDATION.md)。这些验证不能证明 ANR 真机触发、MetricKit crash/hang 的投递时间或业务上传成功。
