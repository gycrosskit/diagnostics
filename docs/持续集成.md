# 自动回归门禁

[Component regression](../.github/workflows/regression.yml) 的当前工作树候选保留既有 required job 名称，新增范围判断与单一公开校验。候选尚未合入，线上生效以真实 Actions 运行为准；跳过/轻量完成不等于执行了平台测试。

| 入口 | 验证 |
| --- | --- |
| 源码 PR / 不填版本的手动运行 | 脚本/契约、四模块 JVM/Android 定向测试与编译、实际声明的 iOS/OHOS 编译、真实宿主架构 iOS simulator 测试与 Swift typecheck |
| 纯文档 PR / main push | 轻量脚本与配置检查；未知路径保守按源码处理 |
| Release published / 手动指定已发布版本 | verify-public 一次校验冻结归档 SHA-256、精确 tag/commit、完整 publication、公开 POM/GMM/变体；通过后独立 JitPack JVM/Android 消费和 iOS Framework/OHOS .so 最终链接 |

PR 不再反复消费旧 rc.5 基线。consumer 不使用 mavenLocal、源码或 staging 替换远程依赖；consumer 是框架无关的网络/存储入口，CMP 与 Kuikly 复用同一公开 API。当前源码字节码目标为 Java 17，旧版本限制只作为历史记录保留。

缓存、Native 下载停滞检测、有限网络重试与首失败收据遵循[共用 CI 规则](https://github.com/gycrosskit/.github/blob/main/docs/持续集成门禁.md)。不自动重跑失败的编译/行为测试，不以静默编译判断下载停滞。JUnit 必须实际执行 test case；外部 Action 固定完整 SHA，CI 不使用生产凭据，测试网络为 MockEngine 或 loopback MockWebServer。

OHOS Kotlin 编译/最终 .so 链接不等于 ArkTS HAR 或设备验收；diagnostics 没有 HAR。系统崩溃投递、真机网络打印与上传由宿主设备另行验收。

以下按版本保留历史验证，不能代替当前候选或新版本的验收。

## 网络采集定向回归

源码验证覆盖请求/响应关联、环境快照、脱敏、完整正文额度、one-shot、提前关闭、流式响应及异常保真。发布前补充的解析前限深检查，用 28 KiB 的 14,000 层数组在旧候选 JAR 复现 `StackOverflowError`；新实现先检查容器深度，再调用 JSON parser，并保留根 depth=0 的原有边界及转义引号行为。

该修复的定向 JVM/Android/iOS simulator 回归执行 91 项测试（core 31/26/18，Ktor JVM 11，OkHttp JVM 5），全部通过；旧候选归档作废，重新冻结发布产物。上述是源码回归次数，不与远程消费者测试或设备验收合计。

rc.6 的 JVM JAR 为 major 61，但 Android AAR 内的 classes.jar 为 major 65；发布 Java 17 消费中两项 Android 测试在首次加载 `BoundedReportWriter` 时真实失败。rc.6 标签与附件保持不可变，修复以 rc.7 发布；归档的 `--max-jvm-major 61` 同时检查 JVM JAR 与 AAR 内 Java 字节码，不能改消费运行 JDK 掩盖这个兼容问题。

## rc.8 外部 Header 策略

`redactHeader` 完全替代默认 Header 值策略，未传入时保留既有安全规则；Body 原文和 1..32 KiB 额度复用现有回调。core commonTest 验证默认放行、外部原文/遮盖、null/异常、数量与 CR/LF 约束，以及旧九参数位置、命名、尾随 onLog 和新增回调的源码兼容。

本机 JBR 21 执行 core JVM 34、Android 29、iOS simulator 21、Ktor JVM 11、OkHttp JVM 5，共 100 项通过；core iOS arm64/OHOS API 编译通过。归档仍检查全部 JVM JAR/AAR 为 major <=61，Java 17 实际运行由 CI 单独覆盖。独立 Maven consumer 从 rc.8 起编译新增公开回调，旧版本基线不引用不存在的 API；发布后的公网文件和最终链接按现有门禁验收。
