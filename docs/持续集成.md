# 自动回归门禁

工作流：[Component regression](../.github/workflows/regression.yml)，包含 `contracts`、`android`、`native`、`release-android`、`release-native` 五项检查。只有真实 Actions 运行成功后才登记为必需状态检查；不把零检查、未执行任务或配置文件存在当作通过。

| 入口 | 验证 |
| --- | --- |
| PR / main push | 既有 Maven checker / metadata 修正契约，shell 语法；四模块 JVM/Android 测试或编译；core、通知、Ktor iOS/OHOS 编译，真实宿主架构 iOS simulator 测试；Swift typecheck |
| PR 已发布基线 / Release published / 手动指定版本 | 冻结 Release Maven 归档 SHA-256、POM、GMM 变体、文件摘要、内部版本、全部 publication；独立消费者只从 JitPack 解析指定版本，JVM/Android 测试、iOS Framework/OHOS .so 最终链接 |

rc.5 的既有 JVM 包为 Java 21 字节码，基线消费使用 Java 21；rc.7 的四模块 JVM 与 Android AAR 字节码目标均固定 Java 17，源码与新版本消费在 Java 17 验证，避免打包机器改变消费要求。

PR 的远程基线固定 rc.5，只验证已有发布渠道和消费者回归；rc.6 的新适配由源码测试先验证，发布后再以 rc.7 解析远程模块。源码与已发布消费者分别执行。PR 不能凭旧版本消费证明候选源码已经发布；Release 验证失败必须处理并保留失败记录，不能覆盖已有不可变附件。consumer 是框架无关的网络/存储入口，两种 UI 均调用相同公开 API；不添加 Compose/Kuikly 依赖来伪造两套网络业务。

GitHub-hosted macOS 的架构通过 uname 确认，选择对应 simulator；JUnit 必须至少执行一个 test case。重构建单任务、max-workers=1；Actions 只读权限，外部 Action 固定完整 SHA，不访问生产凭据或调用短信/通知接口。测试网络为 MockEngine 或 loopback MockWebServer。

CI 给 JDK URLConnection 配置 30 秒连接、60 秒无读取进展超时。这版 Native 下载器未自行设置超时，网络断流时会持续打印相同下载字节数；超时使它进入现有 IOException 重试，不新增测试重试或修改编译器。一次持续传输可以超过 60 秒，只有阻塞读取受限。

Native 编译与模拟器测试使用同一 Gradle JVM，复用成功解析后的 DNS 缓存。[运行 37310269945 attempt 1](https://github.com/gycrosskit/diagnostics/actions/runs/37310269945/attempts/1) 的六项 iOS/OHOS 编译全部通过，但后续新 JVM 连续三次 DNS 失败，模拟器测试未启动；这次失败保留记录，不计为测试通过。

DNS 预热仅尝试三次，失败后记录并继续正常 Gradle 解析，不能作为额外硬门禁。[运行 37314326459 attempt 1](https://github.com/gycrosskit/diagnostics/actions/runs/37314326459/attempts/1) 在初始化预热失败时直接终止，尚未确认缓存能否满足真实依赖；移除这处硬阻断后，实际缺失依赖、测试失败和 JUnit 执行断言仍会正常使门禁失败。

OHOS Kotlin 编译/最终 .so 链接不等于 ArkTS HAR 或设备验收。diagnostics 没有 HAR；系统崩溃投递、真机网络打印与上传仍分别由宿主设备验收。

## 网络采集定向回归

源码验证覆盖请求/响应关联、环境快照、脱敏、完整正文额度、one-shot、提前关闭、流式响应及异常保真。发布前补充的解析前限深检查，用 28 KiB 的 14,000 层数组在旧候选 JAR 复现 `StackOverflowError`；新实现先检查容器深度，再调用 JSON parser，并保留根 depth=0 的原有边界及转义引号行为。

该修复的定向 JVM/Android/iOS simulator 回归执行 91 项测试（core 31/26/18，Ktor JVM 11，OkHttp JVM 5），全部通过；旧候选归档作废，重新冻结发布产物。上述是源码回归次数，不与远程消费者测试或设备验收合计。

rc.6 的 JVM JAR 为 major 61，但 Android AAR 内的 classes.jar 为 major 65；发布 Java 17 消费中两项 Android 测试在首次加载 `BoundedReportWriter` 时真实失败。rc.6 标签与附件保持不可变，修复以 rc.7 发布；归档的 `--max-jvm-major 61` 同时检查 JVM JAR 与 AAR 内 Java 字节码，不能改消费运行 JDK 掩盖这个兼容问题。

## rc.8 外部 Header 策略

`redactHeader` 完全替代默认 Header 值策略，未传入时保留既有安全规则；Body 原文和 1..32 KiB 额度复用现有回调。core commonTest 验证默认放行、外部原文/遮盖、null/异常、数量与 CR/LF 约束，以及旧九参数位置、命名、尾随 onLog 和新增回调的源码兼容。

本机 JBR 21 执行 core JVM 34、Android 29、iOS simulator 21、Ktor JVM 11、OkHttp JVM 5，共 100 项通过；core iOS arm64/OHOS API 编译通过。归档仍检查全部 JVM JAR/AAR 为 major <=61，Java 17 实际运行由 CI 单独覆盖。独立 Maven consumer 从 rc.8 起编译新增公开回调，旧版本基线不引用不存在的 API；发布后的公网文件和最终链接按现有门禁验收。
